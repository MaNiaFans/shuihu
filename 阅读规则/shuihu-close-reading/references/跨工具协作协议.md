# 跨工具协作协议（2.8）

适用于在任意IDE、网页会话、命令行工具或本地／云端模型中执行本项目。它补充[逐回执行合同](逐回执行合同.md)和[派工与恢复](派工与恢复.md)，不降低其中的阅读、独立性与验收标准。遵守实际环境的上位指令；无法满足任务要求时说明具体缺口，不能伪装完成。协议不假设任何产品具备多agent、文件系统、上下文隔离、可核实模型名或自动通信能力。


## 成稿、短任务包与版本核对

总编实际采用跨工具执行时首次完整读取本协议，未变内容复用，更新只补受影响条款；普通角色读执行简令和当前任务指定段落。初读、独立观察和文学修订的任务消息不再重复整份协议、历史报告、哈希表、时间审计或未受影响的全局结论。任务包只保留角色、目标章节、允许输入、可写路径、证据截止和停止条件。

各工具遵守同一交付要求：新章04直接面向读者，完整经过、人物变化和解释清楚，管理记录各归其处。可读性与完整内容复核一起检查，不另加一轮固定审批。已有成果编辑依合同复用既有证据，不因换工具、旧送审用语或规则升级重建01／02。

版本指纹由总编统一机械核对，不进入日常派工回报。检校者已明确指出的单行定位或元数据差错，按合同第五节由总编留历史、修正、核差异并在07关闭机械项和对应当前版本；不再派agent重报版本或重签03。原内容检校继续有效，内容判断的修改仍须独立复核。

## 一、角色和决定权

| 角色 | 可以决定／执行 | 不能代办 |
| --- | --- | --- |
| 总编（本项目主协调者） | 范围、资料基线、角色指定、首次固定核验、争议与返工范围、G1—G7验收、全局变更 | 不常规代写01—05，不代签检校结论，不将摘要当内容检查 |
| 外部执行协调者（可选） | 在指定回目内派两个独立阅读角色，安排后续修订／检校，记录08；已获一次委托授权时核首次固定后继续 | 不兼写01—05，不伪签总编固定回执或最终验收，不改00／07／规则／全局表，不转包协调职责 |
| 阅读者／指定修订者 | 全文阅读01；固定后按意见修订04／05、留历史及处理说明 | 不读他稿形成初读，不写02／03，不自称整回验收，不再委派 |
| 独立检校者 | 新上下文独立全文阅读02；放行后写03；完整复核04／05；追加后续复核 | 不在02固定前接触初读分析，不兼写送审稿，不覆写01／02／03旧记录，不再委派 |
| 用户转交 | 将选定的单阶段命令、允许输入和回执转给指定工具／会话 | 无需代替任何角色判定文学质量；“文件交回”不自动表示验收 |

普通章节采用两位执行者即可。一个工具能开独立上下文时可以同平台完成；也可由不同工具各负责一位。不同工具、不同模型、不同窗口或新标题均不能单独证明独立性。总编与可选执行协调者是管理角色，不增加一次常规全回阅读。

## 二、任务包与输入隔离

每个任务包必须有：唯一任务ID、当前角色与阶段、目标回目、证据截止、项目实际绝对根路径或附件映射、规则版本、允许输入、唯一可写文件、实际前置条件、交付证据、停止条件。未填实的字段不是授权。ID由协调者在原委托ID下追加角色／阶段／接任后缀即可；同阶段恢复沿用原ID，不为登记另建表。已有文件先核存在和版本，不得静默覆盖；看到同一输出已有任务在写，按唯一写入规则处理。

用户向执行端发送填实的角色命令，构成该回、该角色和该阶段的实际派工；执行端记录这条最新指令，不把过期范围文件当作否定新指令的理由，也不据旧全书目标扩大单回范围。全局任务范围仍由总编在交接时更新。

总编／执行协调者核全局状态后形成**中性任务包**。初始阅读者与独立检校者只获得：

- 执行简令、任务指定合同段落和中性章节入口；根AGENTS绝对路径显式提供，不要求每个角色重复读全部管理规则。
- 当回00来源、完整正文、实际附属材料；必要时按任务包回读已读回目的原文。
- 当前角色指令与输出路径；不含研究结论、待验证答案或预设重点，版本信息由总编掌握。

01／02固定前，不读对方文件、03—08、旧回分析、全局追踪内容、项目工作流设计、整份派工手册、启动包、主会话历史或另一模型总结。不能通过全仓库搜索、检索增强、项目记忆或自动摘要变相读入。协调者须检查实际能看到的自动附加上下文与工具配置：能使用最小输入工作区时优先使用；仅共享目录加提示词属于约定隔离，不能声称已做技术隔离。平台内部无法观察之处写“不可核实”，同时保留可见的实际输入；若连初始输入是否夹带他稿也无法合理确认，独立性保持待核验。

已确认接触初稿观点或历史检校的上下文不能靠“忘掉它”变成独立02。原产物保留、说明接触，依合同安排新上下文写未占用的02轮次；有效的另一份阅读不会自动失效。不得复制带答案的对话再声称是新上下文。

完整项目副本可给总编／执行协调者用于管理。实际派给初始阅读角色的输入必须仍满足以上边界。仓库入口相对路径按所在文件解析，任务包注入本次实际根目录；迁移时记录旧根→实际根，不把历史盘符复制成当前命令，不为盘符或链接美观改写冻结研究稿。需要旧原文时只按回目和行号取得，不开放未来章节全文。

## 三、阶段与一次委托

| 阶段 | 进入条件和操作 | 对外状态／停止点 |
| --- | --- | --- |
| 准备 | 核任务范围、当前最早未完成回、00及规则基线，确认两个角色的实际独立输入与唯一输出 | 待准备；缺资料列具体文件 |
| 首次阅读 | 两个新上下文各自按顺序完整阅读，分别交01／02及自己的回执；各自保存后结束本阶段 | 首次阅读已交付，待总编固定核验；不自动读对方稿 |
| 首次固定核验 | 核01／02实际产物、覆盖、具体观察、资料接触和先后；缺口先补实 | 默认总编记07；已授权一次委托时由外部协调者记08实际核验，总编最终复查，不伪签总编回执 |
| 对照 | 总编07或获一次委托授权的外部协调者08已有实际首次固定核验记录，且输入版本一致；原检校者才取得01、允许的前情入口，完整对照写03 | 对照已交付；保留02原件 |
| 修订 | 有效01／02与首轮03固定；阅读者或指定接任者处理全部意见和旧问题，写04／05 | 修订已交付并冻结，待整稿复核 |
| 完整复核与必要返修 | 检校者完整检查04／05；内容问题退作者、留历史，再核全部影响；机械差错依合同第五节 | 无阻断后交总编验收，版本核对不另设agent关卡 |
| 交接B：总编验收 | 核03具体内容证据、意见闭合、版本、05全部变更；先G1—G6，再实际落实并回读G7 | 仅总编能登记整回“验收通过”或具体返工／待核验 |

用户已明确一次委托时，外部协调者按上表完成首次固定核验后组织本回对照、修订、整稿复核及必要返工，不要求用户逐阶段转发或再索总编回执。未获该授权时由总编核固定并给一次阶段许可。两种方式都须先实际固定01／02、核覆盖与输入隔离，再给检校者01；只在08写清实际过程和允许的下一阶段，不冒称总编已审核。最终G1—G7及全局更新仍由总编完成。

两种首次固定核验记录效力只限开放本回后续执行；不增加第二张回执或固定审批，也不替代总编最终复查。记录应指明采用的01／02、覆盖及隔离核查结果、实际记录者和下一阶段；以真实核验内容为准，不以旧“交接A”名称索取额外手续。

阅读者01固定后可按任务包准备前情，不读取未固定的02／03；检校者02固定及首次核验完成前不得接收他人观点。等待依赖时结束本阶段，不轮询等文件。

本回验收后，只有本次执行范围明确包含后续回，且取得总编给出的新回中性任务包，才启动下一回；长期全书目标不扩大一份单回任务包。已授权连续任务无需用户逐回批准，所需的总编审核是研究流程，不是向用户重复索要授权。

## 四、文件权限和版本

| 文件／目录 | 唯一内容写入责任 | 规则 |
| --- | --- | --- |
| 00、来源、底本 | 总编／明确指定的资料准备者 | 执行者只读，疑似错误提交证据，不静默修源 |
| 01 | 阅读者 | 初次固定后不覆写；补读另存并说明受他稿影响情况 |
| 02 | 独立检校者 | 固定后不覆写；失效观察保留，新轮次另存 |
| 03 | 当前指定检校者 | 只追加、署名轮次，原意见与自误均留痕 |
| 04、05及相应历史副本 | 阅读者或明确指定的接任修订者 | 首次送检后变更先留历史，逐项说明改动及依赖 |
| 07、全书追踪各表 | 总编 | 外部仅提交建议和证据，不代写验收或修改编号状态 |
| 08外部执行记录 | 指定外部协调者；无此角色时由总编归集 | 只记事实过程与证据入口，不重写分析，不冒充验收 |
| 规则、模板、用户手册 | 获授权的规则维护者 | 研究执行者不得为自身交付修改标准 |

同一文件同一时刻只有一位写入者。工具切换、会话中断或取消未确认时，沿用派工规范的隔离输出策略；迟到产物留存，不按“最后保存”自动选稿。接任先确认角色及有效输入，只续未完成阶段；不重新生成可信01／02。

**派发前登记唯一执行端。**共享目录的外部协调者先以文件系统“仅当不存在时创建”的排他方式建立08的首段所有者记录，写任务ID、实际工具、自建执行ID、可核实会话标识和允许输出，再回读确认；“先检查不存在、再普通写入”不算排他创建。08已存在时不得覆盖或自行夺取：同一执行者恢复可沿其可核身份续记，另一执行者或无法确认身份时，交总编在07核定沿用、接任或隔离路径，然后才派工。暂未产生01／02不代表目录无人占用。协调者不得提前创建阅读产物占位。

无法排他创建、使用不同设备副本而没有共同登记、或以手动双会话方式派工时，由总编先在07登记本任务的唯一执行端／每个角色、输出路径及中性派工标识，再把仅含该角色身份与路径的派工回执交给执行者；初读／独立观察者不读取07全文。用户只需一次交代工具分配，总编整理可转发命令。没有唯一登记证据时保持待派工，不能让两套角色先写再选。文件排他登记只防重复派发，不替代独立性或内容验收。

Git提交只代表提交里的字节，不包含未提交文件。交接前由总编列本次输入清单并实算版本指纹；取得旧仓库但缺当前本地成果时，先补齐基线。执行者没有哈希工具时不因版本计算停工。送检后不自动格式化、统一换行或改路径。哈希不一致先比较差异；纯传输差异核实并重新绑定，内容变化按影响范围复核，不能直接改03哈希冒充原检校者已看过。

不同工具使用各自工作副本时，交付按任务ID收集原样文件及历史，审核后导入；不双向自动覆盖主工作区。使用共享目录时，不允许两个工具同时维护04／05或03。提交、推送、合并及公开发布依用户实际授权处理，研究任务本身不自动授予发布权限。

## 五、足以复核的交付证据

角色每次交付在消息中提供以下回执；完整正文、观察和审稿意见写入对应文件，不在回执复制全文：

```text
任务ID／角色／本次阶段：
实际平台、请求模型设置、可核实模型、会话／agent标识：
输入文件、实际读取范围、截断与补读、其他资料接触：
输出文件实际路径、检查范围、关键证据所在行或小节：
本次完成／未完成、阻断问题、保留分歧：
原始产物固定情况、所复核稿件版本、历史副本：
下一动作及明确停止点：
可提供的原始工具／阶段消息记录；不可取得的记录及限制：
```

记录公开可见的工作事实、证据和判断摘要，不索要私有思维链。消息ID、时间、模型名、工具日志只有真实可得时才填写。真实的执行说明、具体覆盖与内容产物是证据；不能事后编造日志来“补强”独立性。没有完整工具日志不自动推翻所有工作，但若关键顺序或独立输入缺乏足够可核证据，相关项仍保持待核验，按最小缺口补实。

08按任务顺序归集：任务包、角色／独立上下文、实际启动、01／02固定记录、首次固定核验依据（总编07或本执行协调者08）、03／04／05交付与复核版本、取消和接任、阻断与恢复点。一次委托由执行协调者实际核验时，不虚列或另索总编回执。已有消息可引用可访问入口；不能用失效会话链接作为唯一证据。总编取回后核实并在07登记，不把08原样抄成“通过”。

只有网页对话或不能写文件时，按文件名交付完整文本，注明“待落盘”，不能声称已经写入本地。总编原样保存、比较交付内容与实际文件，并在07记录对应关系；不因执行端不能计算版本指纹停工。

检校者必须实际检查相应的完整04／05，03注明所检查的文件或完整文本及范围。已经检查同一份完整交付，且总编确认保存未改内容时，直接沿用；无需让检校者再次为落盘或新指纹回报确认。只有传输遗漏、内容发生变化或无法确定检查对象时，才补齐实际核验；语义变化须交检校者检查。总编不改03原文、不代签独立复核，单行机械差错按合同第五节记录在07。

## 六、审核意见与返工

总编意见写在07，检校者意见写在03，采用同一信息结构；总编意见编号可用`CH014-E01`，检校者使用本回既有编号。不要因编号不同重复计为两个问题。

| 字段 | 必须写明 |
| --- | --- |
| 编号／级别 | 阻断验收、可保留分歧或表达建议 |
| 问题对象 | 文件及行／小节、当前稿版本；涉及哪个G条件 |
| 证据 | 具体原文和必要上下文；或实际覆盖／版本／阶段缺口 |
| 影响与最小改动 | 涉及哪些结论、人物或交接项；仍有效的证据与范围 |
| 执行与复核责任 | 指定作者修订、另一上下文检校，不让作者自签关闭 |
| 关闭条件 | 修改位置或有据反驳、检校复核入口、绑定版本；未知不要求凭空补答案 |

作者在05逐条回应，检校者在03逐条复核，总编核后关闭07对应项。不把有据分歧统一成一说，不用多数票裁决。无新问题且达到关闭条件就结束返工，不凑轮次。再次出现同一未解决意见且没有新证据或有效修订时，协调者汇总双方依据交总编处理，不无限互相退稿。

旧章返工必须先有总编07中的具体新增问题、可复用版本、最小范围和停止条件。未变的旧证据、原文未详、接任者不同或管理索引未合并不构成全回重读理由。完整复核和重新做02是不同动作，依合同分别判断，不能混称。

## 七、失败、恢复与可执行边界
