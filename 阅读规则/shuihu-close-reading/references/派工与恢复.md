# 派工与恢复

现行版本：2.8，2026-10-25。仓库入口相对路径按文件所在目录解析；下面任务包的根路径由总编填本次实际目录或附件映射。

供担任研究总编与项目协调者的主协调者使用。常规配置为阅读者和独立检校者两个执行角色；主协调者管理范围、派工与验收，不常规兼任修订。不要把整个项目历史、工作流示例或已经形成的分析直接转发给独立检校者。

跨工具模式先读[跨工具协作协议](跨工具协作协议.md)。外部协调者仅在明确任务包内派工、核实际交付并记08；用户已授权一次委托时可实际核首次固定后继续本回后续阶段，不伪签总编回执或最终验收，不代填07。用户只需转发[派工手册](../../../协作派工手册.md)的短委托，输入隔离与唯一写入责任照常执行。


## 成果导向、最短派工与机械修正

新章的04直接写成读者成稿，事实、解释与可读性在原有修订／检校中完成；总编交付内容与阅读入口。既有成果整理只编辑有效结论并检查表达对应，不因文风或新规则重开原文双读。

新章节默认使用《执行简令》作为 agent 输入。总编依根规则按用途读取并复用已读条款；agent 的任务包只给角色、章节、原文、输出路径、证据截止、停止条件和必要前情，不重复整份合同、历史报告、哈希表或时间审计。agent 回报路径、覆盖、意见、修改和未解决项即可，哈希由总编本地核对。

检校者已指出的单行定位或元数据差错，若不改变内容判断，总编按合同第五节留历史、修正、逐行核差异并在07关闭机械项、建立当前版本对应。无需派agent重报版本或重签03；文学内容改动仍由修订者与独立检校者处理。

## 启动一回

1. 总编依根AGENTS按用途读取规则；已读未变条款复用，规则改变只补差异及受影响段落。每次恢复核当前任务范围、进度和具体差额，确定授权及证据边界。普通 agent 读取执行简令和任务包指定条款。检查现有材料，避免覆盖已有阶段。
2. 准备当回00资料；将 `assets/章回AGENTS模板.md` 的内容写入当回 `AGENTS.md`，相对路径按本skill目录解析。用 `assets/07_执行与验收模板.md` 建立当回07，先填范围与实际状态，验收项保持未核验。
3. 两个阅读上下文只获得共同规则和原文输入。可以并行读取同一回；初读者只写01，检校者第一阶段只写02。两者不得读对方尚在形成的材料。
4. 检校者保存02并结束第一阶段。协调者打开实际执行说明、连续覆盖及观察，确认保存和输入隔离后登记。总编统一核版本；已授权一次委托的外部协调者先在08记录实际固定核验，总编最终核对。缺口补实前不发送01或带答案的下一阶段任务。
5. 在同一个检校上下文继续第二阶段，给出01路径，允许查看当前回的前情交接与必要旧原文，要求写03。其先前02保持不变。
6. 指定阅读者修订04／05，必要时指定接任执行agent；再交检校者完整复核，后续返工仍回到对应执行者。协调者按合同分工核查验收证据，先核G1—G6，再更新交接并核G7，最后登记通过。

如果工具支持 `fork_turns`，两个初始阅读角色均用 `none`；不要继承主线程里已经讨论的本回解释。子agent任务中明确不得再次委派。

## 执行模型与交付约定

- 用户指定模型时优先遵从；用户已授权按角色选择模型时，在当前可调用模型和工具约束内选择，未授权改变设置时保留默认。不同角色可用不同模型，但模型名称不构成质量保证，仍须完整阅读和检校。
- 派工及07分别登记角色、请求的模型／推理设置、实际可核实模型标识和上下文关系。请求值不冒充实测值；工具未返回实际模型时写“不可核实”。无法切换模型时说明限制，不声称完成了不同模型交叉验证。
- 任务包同时写清阶段、证据截止、允许输入、可写文件、交付证据和结束条件。初读或独立观察完成后先固定材料，等待相应下一阶段；不自行扩大范围。
- 实际启动后先简短报告角色与当前读取阶段，不将请求获受理当作启动；按执行简令读取必要规则即可。阶段交付后结束本轮，依赖任务由总编另派。
- 跨工具按任务包采用总编首次固定或已授权的一次委托方式；依赖材料实际固定后再派后续任务。不能预先把全部阶段及他稿交给初始阅读者，也不让用户逐阶段批准文学工作。
- 完成汇报提供实际文件、具体段落位置、覆盖或问题缺口、保留分歧和待办。哈希由总编统一核对；通过03／05／07归集证据，不另写冗长汇总来复述整份研究。

## 运行状态与故障处理

这些阈值只限制无证据的排队／失败重试，不限制正常阅读全文、修订或整稿复核的时间。不为了赶时限缩减内容标准。

| 运行状态 | 所需证据及下一步 |
| --- | --- |
| 已派发／排队 | 工具接受请求或仅显示running、pending_init，不算阅读开始。请求一次实际启动回报，内容含角色和当前读取阶段；未回报期间只称排队或尚未确认启动。 |
| 已启动 | 有执行者实际读取说明或可见工具读取证据；不依赖文件存在即认交付。后续用阶段性进展判断，不套排队超时规则。 |
| 已交付并冻结 | 执行者明确交付且总编核实际文件、版本；文件写到一半不送检。完成当前阶段后结束回合，依赖齐备再followup，不让角色轮询等文件。 |
| 待独立复核／待验收 | 分别受03整稿复核和G1—G7证据约束，派工回报不替代完成证据。 |
| 资源阻塞 | 保留具体未完成阶段并附错误原因、冻结输入、下一动作；不登记验收、也不把旧证据作废。 |

- **模型选择与重试**：优先沿用本项目最近实际成功的配置及已有可用上下文，不为取得不同型号而逐个试模型。仅已授权选择设置时可换配置；用户明确指定不可替代的型号仍优先，失败如实报告。同一角色的同一未完成阶段第一次启动遇容量／短暂服务错误，可换一次已知可用或默认配置；原尝试加这一次备选共最多两次，不遍历型号。尝试次数按角色和阶段累计，恢复上下文不清零；达到上限先保存阻塞，只有服务恢复证据或用户明确要求重试才开新尝试。
- **排队上限**：记实际派发时刻，默认每30—60秒最多检查一次；连续约120秒仍没有实际启动证据，就结束本次等待并按上述备选／阻塞处理。长工具等待每次不超过60秒。已有真实工作进展的角色不按此取消。无新增进展时不反复输出泛泛的“正在研究”。
- **额度／余额／权限错误**：明确返回额度用完、余额不足或权限拒绝时，立即停止依赖该资源的派工与重试，不靠换型号或新会话绕过。能做的版本保存、范围登记和差额整理照常完成，及时向用户报告准确阻塞与恢复点；没有恢复证据不重复探测。不推断额度何时恢复，也不为验证规则继续消耗同一不可用资源。
- **取消与写入责任**：interrupt的调用成功或返回previous_status不证明旧角色已终止。核当前状态并发取消说明；旧角色仍pending_init／running或终止无法确认时，不给新角色同一写入路径。确需接任且有可用槽位，使用不重名的隔离输出路径并明确唯一采用者，旧角色迟到产物只存档；旧角色未确认终止前，采用稿保持隔离路径并直接绑定该路径及哈希送检，不转存到旧角色仍可能写的路径。旧角色确认终止后，总编才可逐字节转存到规范路径并登记一致哈希，不代写内容。无槽位则记录阻塞，不持续spawn。初始02的独立性边界在隔离路径上也不放宽。
- **接任**：任务包称“接任者”，标明原01／02／03的真实作者和有效范围，不用“你已完成原02”灌入虚假经历。只接未完成阶段；原阅读覆盖或独立性有具体缺口时才按合同补做。正式复核在冻结04／05取得后再派，不提前占槽等稿；初始01／02仍可并行。
- **资源信息**：07只记本次需要的成功配置、尝试次数、错误、启动证据和恢复动作；不另建轮询服务或自动重试任务，不记录凭据。用户状态答复说清最近实际交付、当前阻塞及剩余步骤，不将排队时间算成研究进展。

## 前情与交接的最短完整路径

01固定后，阅读者可在检校者形成03期间只读前回交接并准备修订；它不读取尚未固定的02／03。两份初读和首轮03均固定后，一次任务处理03与前情，写04／05并完整自核后交付。仅在确有交接需要时另存前情备忘；不把“备忘—总编全文再读—再次派工”设为每回固定关卡。

派工提供当前有效文件、版本、未完成步骤、允许输入与输出，不复制旧章的整份长报告。依合同第七节，以前回已验收完整清单为入口核全部旧问题，追读差额与疑点；作者和检校者分别完成自己的核对，不能由一方的完成声明替另一方。总编复用本会话实际读过且版本未变的证据，记录入口即可；03完整内容检查证据与05变更仍须实际核查。

首次04／05复核始终完整执行。没有阻断、版本一致且交接落实，就完成验收；不为凑轮次加审。发现具体错误才按影响范围返修并复核，完整阅读全文和文学判断不能改成关键词检查。

## 检校第二阶段与修订复核

第二阶段任务只在01／02确认固定后发送：给任务ID、规则版本、实际根目录、阶段、有效输入、唯一输出、核验记录及停止点；首次固定核验可记总编07或获一次委托授权的外部协调者08，不另索总编回执。指定01路径，要求按合同逐项对照原文，写03，独立观察不改；如有未获准打开的资料，先说明具体需要，由协调者依据既有授权提供。

修订任务交阅读者或指定接任执行agent，明确04／05的作者、有效01／02及03、前回交接和全局表只读范围、意见编号与历史保留要求；禁止作者改写03的结论。派工必须直接写明：04交付可直接阅读的逐回总结与人物分析，先讲清完整经过和人物变化，再展开重要细节；关键判断就近给短引和定位，保留重要限定及受影响者，不堆管理说明或另造同内容阅读版。05保留全部旧问题状态与直达依据，只展开新增、变化和疑点，提出具体全局变更和证据，由检校者复核，不能把研究与拟稿留给主协调者。

复核任务明确当前稿路径、变更范围和待复核问题；首次完整检查04／05，一并检查故事是否讲清、人物理解是否有据、重要动作与限定是否保留，不能只核文件和格式。后续内容修改检查全部影响及依赖。检校者在03追加实际对象、范围、证据位置、闭合及分歧；版本计算和保存稿对应由总编处理。材料齐备后合并同阶段意见和修正，沿用可用上下文，满足完成条件即交回。

无文件工具时按跨工具协议第五节交付完整文本，总编保存并比较内容。已经确认为相同内容的保存或机械定位修正，不再派检校者单独报版本；未经检查的内容仍须实际复核，不能由总编代签。

主协调者实际核查03的内容检查记录、01／02覆盖和固定证据、意见闭合及当前哈希，按需查对应稿件和原文；核验05的具体跨回变更后落实全局表并回读，最后更新07。普通修订退回作者，实质冲突明确原文范围并安排返工或专项复核，不默认重新读完所有稿件。

## 中断后的恢复

- 先判断本次是新章继续、原阶段续做还是已验收旧章的具体返工；在当前授权内推进最早未完成项；只有本次授权包含新章时才推进新章。先核已有验收证据和当前哈希，不能把“新上下文”误当作旧成果作废。
- 旧章派工前在07填实新增问题／证据、可复用版本、最小修改与原文范围、停止条件。仅有索引归并或明确局部差额时，采用合同的专项复核，不重新生成01／02。原执行者不可用不单独构成全回重审理由；无具体问题则不派重复任务。
- 主协调者先读现行规则与07，再看实际存在的产物；不以会话摘要或“上次说完成了”代替文件。恢复到最后一个有证据完成的阶段。承担新02独立观察阶段的检校者只接收中性的原文任务包，不转发07或恢复讨论；合同所定义的旧章专项复核者不承担新02，可读既有检校与交接并如实说明接触。
- 若原文完整阅读不能从已留范围与实际材料确认，补读缺段；缺口不明则重读全回。不要事后编造读取顺序、时间或agent标识。
