# 派工与恢复

供主协调者使用。不要把整个项目历史、工作流示例或已经形成的分析直接转发给独立检校者。

## 启动一回

1. 读取根AGENTS、skill、执行合同、当前任务范围与进度，确定用户授权及本次证据边界。检查现有材料，避免覆盖已有阶段。
2. 准备当回00资料；将 `assets/章回AGENTS模板.md` 的内容写入当回 `AGENTS.md`，相对路径按本skill目录解析。用 `assets/07_执行与验收模板.md` 建立当回07，先填范围与实际状态，验收项保持未核验。
3. 两个阅读上下文只获得共同规则和原文输入。可以并行读取同一回；初读者只写01，检校者第一阶段只写02。两者不得读对方尚在形成的材料。
4. 检校者保存02并结束第一阶段。协调者检查文件内容、覆盖情况和实际哈希，登记阶段；在此之前不发送初稿观点或第二阶段任务。
5. 在同一个检校上下文继续第二阶段，给出01路径，允许查看当前回的前情交接与必要旧原文，要求写03。其先前02保持不变。
6. 指定阅读者或协调者修订04／05，再交检校者复核；处理后续问题。协调者先核G1—G6，再更新交接并核G7，最后登记通过。

如果工具支持 `fork_turns`，两个初始阅读角色均用 `none`；不要继承主线程里已经讨论的本回解释。保留原模型设置，除非用户另有选择；记录实际可见信息，不填猜测的模型名。子agent任务中明确不得再次委派。

```text
原文输入：{本回00来源、正文、实际附属资料的绝对路径}。
必要前情只给原文：{已有前回原文路径及需要回读的范围；无则写无}。
按原序读完整正文，遇截断补读，保存连续覆盖和实质细读。
只写：{本回01绝对路径}；其他分析稿、全局表和规则均不改。

```

## 独立检校第一阶段任务包

```text
你是第{NNN}回独立检校者，目前只做独立通读，不进行稿件对照。
先完整读取：
F:/水浒/AGENTS.md
F:/水浒/阅读规则/shuihu-close-reading/SKILL.md
F:/水浒/阅读规则/shuihu-close-reading/references/逐回执行合同.md
本次用户授权：{明确范围}；当前证据截止：{回目}。
原文输入：{本回00来源、正文、实际附属资料的绝对路径}。
必要前情只给原文：{已有前回原文路径及范围；无则写无}。
只写：{本回02绝对路径}，包含执行说明、连续覆盖和独立实质观察。
现在不读取01、03—07、全局追踪内容、工作流设计、他人消息或初稿结论。
保存02后结束本阶段，报告文件与实际资料接触，等待后续对照任务。
不要自行进入第二阶段，不再次委派。
```

主协调者不得给检校者附“重点找出初稿哪里错了”等携带具体观点的提示。两位共享文件系统并不构成技术权限隔离，独立性依据实际派工和可核实记录说明。

## 检校第二阶段与修订复核

第二阶段任务只在02确认固定后发送：指定01路径，要求按合同逐项对照原文，写03，独立观察不改；如有未获准打开的资料，先说明具体需要，由协调者依据既有授权提供。

修订任务明确04／05的作者和意见编号，禁止作者改写03的结论。复核任务明确当前稿路径、变更范围和待复核问题；检校者自行读取文件并计算其实际哈希，将结论追加03。主协调者再次核对文件哈希及意见闭合，然后更新07和全局表。

## 中断后的恢复

- 主协调者先读现行规则与07，再看实际存在的产物；不以会话摘要或“上次说完成了”代替文件。恢复到最后一个有证据完成的阶段。新独立检校者仍只接收中性的原文任务包，不转发07或恢复讨论。
- 若原文完整阅读不能从已留范围与实际材料确认，补读缺段；缺口不明则重读全回。不要事后编造读取顺序、时间或agent标识。
- 02未固定且新上下文已接触01的，不能续称独立观察；保留现有材料并另开独立上下文重做02阶段。按合同使用 `02_独立观察_R02.md` 等未占用路径，07明确有效轮次；已有03由新检校者在完成独立阶段后追加本轮记录，不覆盖旧意见。
- 01漏读须由阅读者补读并另写 `01_补读更正_R02.md`；覆盖无法核实时全回重读并写 `01_复读_R02.md`。07登记本轮有效01和补记，向第二阶段检校者提供这组实际输入，原01仍保留。
- 03已完成但04／05后来改过，旧复核不自动覆盖新文件；比较差异，回查受影响范围，追加复核。
- 旧章节尚无07时只登记现存证据及缺口，不能直接用模板勾满验收。独立性属于历史事实，不能靠重写说明补造。
- 一时无法完成时保存实际阶段、缺口、待执行动作和目标路径；不要把局部结果包装成整回通过。后续恢复仍在原授权范围内继续。

## 规则更新后的只读检验

对流程做实质更新时，向一个新上下文agent提供现行规则与几个具体执行情境，请它给出下一步及完成状态，不提供标准答案。情境覆盖实际风险即可，不强求固定数量，不读取新章正文，不生成正式章节结论。记录实际判断、发现的规则空隙及修订；这只验证流程解释，不证明之后的模型必然遵守。
