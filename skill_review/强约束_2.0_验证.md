# 阅读约束2.0：本轮验证记录

日期：2026-10-22。用户要求为后续agent建立强约束。本轮只维护规则和验证执行流程，未启动第二回，也未重新认定第一回文学结论。

## 落地内容

项目根目录AGENTS指向skill与逐回执行合同；每回入口模板支持从单回目录启动；派工文件规定两个新上下文、检校两阶段及恢复流程；07模板记录授权、实际阅读、有效轮次、意见闭合、稿件版本与G1—G7验收。全局任务范围与研究进度分开登记。

## 独立情境检验

`/root/reading_rules_audit` 以不继承主线程的新上下文，完整读取根AGENTS、skill、执行合同、派工与恢复、07模板，进行只读判断。未提供标准答案；未让它读取小说或第一回分析、生成章节成果或改动文件。后续补充要求它检查恢复时的路径与前置条件。

## 发现并修正的衔接问题

1. 原skill允许协调者兼任初读，与派工要求两个新上下文不齐。已明确01与02各自新上下文，协调者可承担04／05修订。
2. 原规则要求重做独立观察却未指定旧02已存在时的路径。已加入轮次命名、原稿保留、07的当前有效输入表，以及新检校者接触旧稿的时点；01漏读也有实际补读／复读及更正文件。
3. 07原初始状态“待验收”与尚未执行冲突。已改为“待准备”。
4. 已明确01固定后再接触交接判断、只有协调者恢复时先读07，以及G1—G6核验后更新交接并核G7、最后登记通过。

上述修改后，由同一检验者回看现行文件的实际文字，核验角色分离、轮次与有效输入、模板初始状态、01固定后交接、恢复权限、G1—G7顺序六处衔接。其补核结论为“本轮六处补核通过”，在这些修改及相互衔接范围内未发现新的实质矛盾。该结论不扩张为章节研究或文学验收通过。
