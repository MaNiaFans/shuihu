# 水浒逐回细读与检校

执行版本：2.3，2026-10-23。在2.2基础上增加有界故障调度、真实启动状态、唯一写入责任及按变化交接；两次完整阅读、真实独立性、整稿内容复核及G1—G7标准不降低。旧章节保留实际执行版本，不追改历史。本次规则修改与检验状态见[维护验证记录](../../skill_review/流程效率_2.3_验证.md)。

## 入口与适用范围

- 全部角色先读项目根目录 `AGENTS.md` 和本文件。章节任务必须完整读 [逐回执行合同](references/逐回执行合同.md)。
- 调度、派工和恢复任务另读 [派工与恢复](references/派工与恢复.md)，依 [执行与验收模板](assets/07_执行与验收模板.md) 建立每回 `07_执行与验收.md`。独立检校第一阶段不读已经填入他人观察的07。
- 用户当前授权由主协调者登记在 `全书追踪/任务范围.md`，不把某次试读的回数写死为永远不变的规则。子 agent 以主协调者转交的最新授权范围执行。
- 整书源文件按所需区间读取。已授权读完全书也须依顺序逐回推进，不在当前回的初读中借未来情节补全空白。回读既往原文允许，结论必须注明当时已读范围。

项目《工作流设计》、旧 skill 包、既有分析和全局追踪表可能含他人判断或后回示例；初读和独立观察阶段不将它们作为必读资料。所需研究要求已在本入口与合同中给全。接触过相关材料须说明，不宣称模型没有既有知识。

## 固定流程

资料核对 → 两个执行上下文各自完整阅读并固定01／02 → 检校者对照原文写03 → 阅读者修订04／05 → 检校者完整复核当前稿 → 主协调者核验证据、更新全局追踪并登记07。

本项目要求初读子agent和独立检校子agent分别以全新上下文启动；支持 `fork_turns` 时均用 `none`。检校者第一阶段只拿规则、原文、来源和必要的旧原文路径，保存02后结束该阶段；主协调者确认落盘与覆盖记录后，才派发第二阶段与01的路径。

前情核对默认在01固定后并入阅读者的修订准备；02固定后检校者才可接触交接。独立的前情备忘不是强制关卡，已有备忘按版本复用，不再复制成另一份准备报告。完整旧问题核对采用合同第七节的状态清单与变化说明，不能用摘要代替当回原文或完整04／05。派工排队、容量故障及额度错误按[派工与恢复](references/派工与恢复.md)处理，未实际启动不报“正在阅读／复核”。

主协调者担任研究总编与项目协调者：准备中性资料、明确范围与模型分工、核验执行证据、处理异常、维护跨回追踪并交付成果。默认不第三次通读全回，不常规代写或修订04／05；疑点只按所需上下文核查，返工交执行者。常规修订由阅读者承担；确需换人时明确指定执行agent，检校者保持独立复核职责，不让其兼写送审稿。主协调者不兼任01初读或02独立观察角色。

01与02均为模型阅读全文后写的充分阅读材料，不能用摘要互相代替。01、02固定后不得覆写；补读、更正与重做按合同使用新轮次文件，并在07标明当前有效输入及失效材料。03只由检校者追加，04／05由指定修订者维护，07及全局表由主协调者维护。

恢复不是默认重做。先核已有验收、版本与具体未完成项，再决定是否需要旧章返工；已验收且版本未变的证据继续有效。主协调者在旧章07先记录新增问题、复用证据、最小范围及停止条件，再派工。只有局部交接或编号问题时，不为换检校者而先重建02；按合同的专项复核处理。原执行者不可用、上下文更换或全局表尚未归并不能单独触发整回重读。没有已证实的新问题时，按用户授权推进最早未完成的新章节。

无法取得独立上下文时，先保存能完成的材料，状态保持“待独立检校”；如用户明确改为单人复核，则标注标准变更和局限，不沿用“独立检校通过”的说法。

## 证据与深度

通读、在场判断、场景划分、人物身份、因果与文学解释均由模型完成。工具只辅助原样复制、显示全文、定位、保存、比较与检查文件；任何程序结果都不能代替对原文的判断。

先写清完整经过，再深入具体动作、用语、物件、关系和知情差异。给予无名者、配角及承受后果的人足够记录。事实与解释的证据规则、覆盖要求和反证要求见合同；不得仅靠增加篇幅、表格或推测数量充当深度。

每个关键主张都须能回到本底本的具体原句及上下文。叙述者、人物、诗词、注释和分析者的声音分清；“某人声称某事”与“某事得到证实”分别判断。原文明示心理予以保留，未明写的心理不能补成事实。解释允许多义，不要求制造阴谋、统一为一解或找满若干伏笔。

## 验收与返工

验收是主协调者逐项检查合同中的 G1—G7 及实际复核证据后的结论。阅读者和检校者承担完整内容检查，主协调者审查覆盖、检校范围与证据定位、问题闭合、版本和交接变更；不把这项验收扩展为惯常的第三轮完整研究，也不凭简报中的“通过”放行。验收材料在既有03、05、07中链接归集，不另写一套重复报告。先核G1—G6，更新交接并核G7，最后登记通过。正文完整、文学覆盖、证据支持、真实独立检校、问题闭合、稿件版本和追踪交接缺一不可。格式和引文匹配通过仅为辅助检查。

有阻断问题则定点返工；修改04／05后须再由检校者检查受影响部分及其上下文。复核记录绑定实际文件的 SHA-256，任何后续改动都必须重新确认对应范围。不得把有据的文学分歧当作事实错误，也不得把事实错误改名为分歧。

未经核验的项目填“未核验”，不能预填通过。过程记录只保留资料、证据、修改理由及判断摘要，不要求输出模型私有思维链。

## 全书整合与规则维护

全书整合启动前逐回核对完成状态；旧试读须如实标明执行版本及缺失记录。主协调者安排整合与独立复审角色，管理范围、疑点和验收；整合agent读全体修订稿、检校意见与追踪材料，逐人核实经历、关系变化、场外事件和遗漏；另一个独立上下文复审者回读支持与相反原文。发现错误须同步返修相关章节、索引和结论，并保留旧判断。不能凭姓名共现或向量命中发布“完整人物档案”。

规则维护任务不得顺带启动未授权章回。对独立性、证据或验收有实质变更时，用一个新上下文子 agent 做只读情境检验，检查其实际如何判定继续、返工或未完成；不给预期答案，不让其生成正式章节成果。格式校验与这种流程检验均不等于全书文学质量保证。
