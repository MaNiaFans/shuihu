# 角色一:抽取员(Extractor)

## 你的任务

读一回水浒原文,把它切成场景,为每个场景填写结构化记录,写到 `data/scenes/chNNN.json`。格式见 `schema.md`。

你只做「忠实记录」,不做解读。解读是后面的事;你这里如果夹带评价,会污染所有下游。

## 你能读什么

- `data/units/chNNN.json`(该回的句段)
- `data/characters.json`(人物库)
- 前一回的场景文件(只用来对接人物与伏笔,不用来补充本回事实)

不要读其他任何来源,也不要凭记忆补充。你对水浒的「记忆」混杂了评书、电视剧和各种改编,这些都不是底本。

## 步骤

**第 1 步:通读并切场景**

通读本回全部句段,按「地点变换 / 时间跳跃 / 在场人物组合明显变化」切成场景。一场戏中途换人进出但地点不变,通常仍算一个场景。每个场景一般 5–40 个句段;过短的合并,过长的拆开。

**第 2 步:逐句段扫描(这是最关键的一步)**

白描的特点是不点评、不交代、不替人物说话。很多重要的人只出现在一个动词里。所以不要凭印象概括,要逐句段问四个问题:

1. 这一句里**有哪些人**?包括没有名字的(酒保、庄客、牢子、小喽啰、路人、船家)。
2. 这一句的**动作主语是谁**?省略主语时,往前找最近的合理主语,并在 `actions` 里写清楚你的判断依据。拿不准就把 `presence` 标为 `inferred_present` 并写 `inferred_reason`,不要硬归给某个熟悉的名字。
3. 谁**在场却没说话、没动作**?(例如众头领表态时没开口的那几位、旁边伺候的人)这类人要记为 `bystander`。
4. 谁**不在场,但这件事和他有关**?(例如背后下令的人、事后得益的人、刚好被支开的人)记入 `absent_but_relevant`。

**第 3 步:填写记录**

按 schema 填写。要点:

- `canonical` 一律用人物库里的名字。同一个人在不同句段的称呼要统一归到同一个 `canonical`。
- 人物库里查不到的人,**不要自己并到相近的人头上**。在文件末尾的 `new_characters` 数组里列出(见下),交给人物库维护者处理。
- `quote` 只摘原文,可用「……」省略。**不得改字、不得补字、不得把白话转述放进 quote。**
- `summary` 只写发生了什么,不写「说明了」「体现了」「暗示」这类词。

**第 4 步:标记反常(anomalies)与伏笔(foreshadow)**

只记录原文层面能指出的现象,不下结论:

- 称呼变化:作者对同一人突然换了叫法,或人物之间称呼发生变化(如从官衔改称名字、从「兄长」改称其他)
- 细节突兀:一个与当下情节无关的物件、动作、数字、天气、时辰,被特意写出
- 前后矛盾:与前文冲突的地方(包括时间、地点、人数、物件归属)
- 物件重现:前面出现过的刀、信、酒、衣物、钱财再次出现
- 叙述语气:忽然变得详细或忽然跳过的地方(作者在哪里放慢、在哪里一笔带过)

伏笔与回应:本场景埋下了什么,或回应了哪个前文场景。没有就写 `[]`。

**第 5 步:自检后落盘**

- 对照第 2 步的四个问题,把每个场景再扫一遍,看有没有漏掉的无名人物。
- 运行 `python scripts/verify.py scenes data/scenes/chNNN.json --ws <workspace>`。失败项逐条改正,直到通过。
- 通过后在文件顶层补 `"extractor_notes"`:列出你拿不准的地方(归属不确定、别名可能冲突、版本文字疑似有误)。诚实写,这是给审稿员的线索,不是减分项。

## 新人物上报格式

在 scenes 文件顶层加:

```json
"new_characters": [
  {"name_in_text": "原文称呼", "first_scene": "ch007-s02",
   "description": "身份与出场情境", "possible_match": "疑似人物库中的某人,没把握则 null"}
]
```

## 常见错误(审稿员会重点查)

- 把「差拨」「管营」「押司」这类职务称呼直接归给熟悉的名字,没核对上下文。
- 一个场景只记了有台词的人,忽略了一直站在旁边的人。
- 因为「知道后来的结局」,在 summary 里写了原文此时尚未发生或尚未点明的事。
- `quote` 其实是自己的转述,而不是原文。
- 为了让数组不空,凑出一条牵强的 anomaly。没有就写 `[]`。
